## 2) Architecture Sketch

### Data model (runtime JSON)
`BroadcastPackage`:
- `urgency` (`BREAKING|DEVELOPING|JUST IN|LIVE`)
- `headline` (string)
- `subheadline` (string)
- `importance` (1–10)
- `anchorIntro` (string)
- `fieldReport` (string)
- `panel[]` (3 items: name/title/take/bias)
- `ticker[]` (8–12 short items)
- `publicAdvisory` (string)

### API contract
- `POST /api/broadcast`
  - input: `{ drama: string, vibe: string }`
  - output: `BroadcastPackage`
- `GET /health`
  - output: service health payload

### Component breakdown
- **Backend:** Express server, LLM prompt orchestration, validation, sanitization, timeout/error/fallback logic
- **Frontend:**
  - Intake form
  - Breaking headline row
  - Anchor desk card
  - Field report card
  - Importance meter
  - Pundit panel grid (3 bias lanes)
  - Public advisory block
  - Animated ticker crawl

### Key technical decisions
- Used existing OpenAI-compatible local endpoint (`qwen3-32b`) for cost-effective generation.
- Added strict server-side validation and content-length guardrails.
- Implemented fallback package generator so UI never returns blank on model failure.
- Kept stack minimal (Node + Express + vanilla frontend) for fast, stable deployment.
