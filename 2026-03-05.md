## 3) Architecture Sketch

### Data model (client runtime)
`TimelineBeat`:
- `sentence` (string)
- `score` (0–100)
- `event` (`big laugh | applause ripple | quiet chuckle | awkward silence`)
- `start` / `end` (seconds)

### Processing flow
1. Validate text length + pace inputs
2. Split text into sentence chunks
3. Score each sentence (keyword + punctuation + length + venue multipliers)
4. Convert to timed beats using selected words-per-minute
5. Render:
   - waveform
   - big-moment list
   - dead-air risk list
   - rescue-line suggestions

### Component breakdown
- Form + validation
- Status pill
- Loading scanner state
- Empty hint state
- Results grid
- Canvas waveform renderer

### Key technical decisions
- Static frontend + Nginx in Docker (fast and reliable overnight deploy)
- No external API dependency (works offline/cheap)
- Deterministic heuristics for predictable behavior in demos
